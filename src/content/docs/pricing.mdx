## Frequently asked

### Does my license expire?

No. Once you buy Pro, it's yours — permanently, and so are all the 1.x updates that follow.
There's nothing to renew for your major version. If Atrium ever ships a 2.0, that would be a new
purchase — but your v1 license keeps working exactly as it does today, forever.

### Is Free actually free, or a trial?

Free is free, forever, with no caps. It's the same organizing core described above — no feature
countdowns, no locked panes, no "upgrade to unlock" popups. Pro is additive, not a key that
unlocks a crippled app.

### Is there a subscription?

No. Atrium has no subscription billing, and never will. You pay once for Pro and get every
1.x update forever — no renewal, no update window, no subscription infrastructure of any kind.

### How does Atrium compare to Solo?

[Solo](https://soloterm.com) is a real, actively developed workspace for agents and dev processes,
and worth knowing about if you're comparing — this isn't a knock on it. The concrete differences,
for the record:

- **Free tier.** Solo's Free caps out at 4 projects and 20 processes (every feature included,
  the gate is pure capacity); unlocking more is $99/year (renewals run $69/year). Atrium's Free
  has no project or process cap at all — the $39 Pro purchase is a one-time perpetual license for
  the augmentation layer (integrations, SSH, notifications — see the cards above), not a capacity
  unlock.
- **Telemetry.** Solo collects basic product-analytics (Aptabase) and crash reports (Sentry).
  Atrium sends none, of any kind, ever — see the [privacy policy](/privacy/).
- **The agent surface.** Solo's MCP server (~40+ tools) includes control verbs —
  `spawn_agent`, `restart_process`, `send_input` — behind a documented lead/worker orchestration
  pattern. Atrium's [MCP server](/guides/agents-mcp/) is visibility-only by design: read the
  cockpit, write TODOs/notes, never drive anything. Control-out is a real future direction, staged
  behind its own opt-in and trust-review surface — not shipped by default today.

Both products are Tauri desktop apps solving an adjacent problem; they just make different bets.
Solo bets on capacity-gated pricing and a wide agent-coordination surface out of the gate. Atrium
bets on an uncapped free tier, pay-once pricing, and a narrower, slower-to-expand boundary between
"showing you things" and "acting for you."

### Why does the Pro app embed an Atlassian OAuth client secret?

Because Atlassian's OAuth flow requires one, and Atrium has no server to hide it on — there is
no Atrium backend, by promise. The embedded "secret" is not load-bearing: the actual security
boundary is PKCE plus a localhost-only callback, so extracting the string from the binary gets
you nothing — it can't read anyone's Jira data without the user completing Atlassian's own
consent screen. This is a deliberate, documented trade-off in favor of "no backend, ever," not
an oversight. (Every API call goes directly from your machine to Atlassian's; nothing routes
through us — see the [privacy policy](/privacy/).)
